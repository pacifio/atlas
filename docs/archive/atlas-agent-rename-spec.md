# Retire "cersei" and "codex" — the native agent is Atlas Agent (`atlas-agent`), the engine is `atlas-engine-*`

Step-by-step spec (2026-09-23). Tick each step off here as it lands; the plan of record for ADR-0011.

## Context

The native agent is already displayed as "Atlas Agent", but the code still says otherwise: the stored agent id is the literal `"cersei"`, Rust and TS identifiers are `Cersei*`, and the vendored engine (`vendor/codex`, a hard fork of OpenAI Codex, 110 crates, ~50k occurrences of "codex" in ~2,300 files) is named codex throughout, including env vars, on-disk names, keychain entries and the `.codex/` project-config directory it reads from user repos. Coding agents keep finding these traces and get confused.

Decisions taken with the user (2026-09-23):

| Decision | Choice | Why |
|---|---|---|
| Engine scope | Full rename of `vendor/codex`: directory, crate names, identifiers, env vars, on-disk names, wire fields, binaries/arg0, OTel, MCP identity | "Complete removal" is not met if `use codex_core::` stays visible in the seam crate |
| Engine crate prefix | `atlas-engine-*` (dir `vendor/atlas-engine`, idents `atlas_engine_*`) | Atlas already owns six MIT crates `crates/atlas-agent-{manager,store,servers,delta,transcript,wire}`; a distinct prefix keeps the MIT/Apache boundary visible and lets the quarantine test keep keying on a prefix |
| Product identity | Atlas Agent / `atlas-agent` for everything user- or model-facing: agent id, env vars `ATLAS_AGENT_*`, home `~/.atlas-agent`, project dir `.atlas-agent/`, keychain, originator, MCP client name, `_meta` keys, OTel metric names, wire fields | The name the user asked for |
| Old data | No migration. Rows under `"cersei"` are deleted by a thread-metadata schema V3 step; localStorage keys not aliased; checkpoint rows degrade to `acp` | Pre-launch; nothing to preserve |
| Docs | Rewrite living docs; archive the port spec + four `codex-*` research docs; keep ADR-0003 verbatim; add ADR-0011; add a guard test | Keeps the historical record while the live tree goes clean |

Verified facts the plan relies on:
- The engine's normal dependency closure from `crates/atlas-native-agent` covers 103 of 108 crates. No crate pruning.
- App-server schema exports and the two `.json.zst` blobs are regenerated by `app-server-protocol/scripts/write_schema_fixtures.py`; a stale blob fails that crate's own tests.
- `code-mode-protocol` compiles protos in `build.rs`; `config` and `exec-server` ship checked-in prost output whose package name appears only in service-path strings.
- insta names snapshots `<crate>__<module>__<test>.snap`; 14 are named `codex_core__*`, 9 have "Codex" in the body.
- `Source::parse` in `crates/atlas-checkpoint/src/store.rs:2589` falls back to `Acp`.
- The `gpt-5-codex` fallback lives only in the dev-only `from_env` path of `crates/atlas-native-agent/src/engine/config.rs:272` and in tests.
- `cerseiProvider/cerseiEffort/cerseiCompress` are in-memory session fields, not persisted.
- Vendoring commit `67fb707d3d5fd35f57726fcb17ed3177bcc34c58`; `git log --full-history -- vendor/codex` still resolves it after the move.
- Nothing outside the engine reads `codex_request_type`, `codex_approval_kind`, `codex_strict_auto_review`, `_codex_executed_tool_call_raw`; the gateway contract (`docs/reference/atlas-ai-api.md` §10.1) names only `org_id`, `user_id`, `feature`, `request_id`.
