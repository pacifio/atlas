Parallel agents

Run a team of agents at once.

Every thread gets its own session worker, so you can fan work out across agents and projects simultaneously — one writing tests, one refactoring, one researching — and watch each one stream its tool calls live.

  • Mix your agents. Claude Code, Codex, and ACP agents side by side — each on the task it's best at.
  • Intervene anytime. Jump into any running thread, steer it, or approve a permission — the rest keep going.

Workspaces

Every project. One window.

An Arc-style switcher holds all your projects in a single window. Hit ⌘. to flip between them — each carries its own editor tabs, terminals, git state, and agent threads, restored exactly as you left it.

  • Instant switch. State swaps from an in-RAM snapshot — no remount, no cold reload of the editor or terminal.
  • Group & pin. Organise projects into custom groups, pin the ones you live in, and see live git +/− at a glance.
  • Running, everywhere. A badge marks workspaces with agents still working — even the ones you're not looking at.
02 · Session capture

Source control
for coding agents.

The record of what an agent did disappears the moment the terminal scrolls. Atlas keeps it. Every session lands on the timeline. Every commit an agent makes becomes a checkpoint, linked back to the session that produced it. Open a session to read the prompt, the tool calls and the response, or ask it questions. Click a row.

  • Local-first capture. Sessions live in .atlas/sessions.db next to the repo — yours to grep, export, or delete.
  • Checkpoints link commits to sessions. Open any commit and see the agent run that produced it, reasoning included.
  • Organisation timeline. One board across every member and project — the shape of a week's agent work at a glance.
  • Redacted at the source. Keys, tokens and secrets are scrubbed on the way into the store, never on the way out.

03 · Teams

Onboard your team.
Start chatting.

Create an organisation. Invite people with a link. The same window grows channels, direct messages and calls with recordings and transcripts. Draft prompts together in real time. Sketch on a canvas per conversation. Hand any message straight to an agent. Everything is scoped to the organisation, so switching orgs switches the whole workspace. Open a channel, switch tabs, try the canvas.

  • Organisations with roles. Admins, product owners, developers, members — invite by link, manage from the switcher.
  • Chat that knows the code. Mention a branch, drop a diff, or send a thread to an agent from the message itself.
  • Calls, drafts, canvases. Voice and video with transcripts, live co-edited prompt drafts, and a shared canvas — the same ones the web app uses.
  • Local stays local. Sync is per organisation and opt-in. An unsynced org is still a full workspace.

Auth flow

architecture/auth-flow.md · updated 2h ago · 4 references
@architecture @auth @security

Token-refresh is opportunistic, not scheduled. The frontend never sees the refresh token; it lives only in the keychain proxy.

Boundaries

  • Access tokens live in memory for the duration of the session.
  • Refresh tokens are written to the OS keychain via tauri-plugin-stronghold.
  • Renewal happens on the backend; failures surface as a single auth.refresh.failed event.

Open questions

  • Do we eagerly refresh on app focus or wait for a 401?
  • How long should the keychain entry persist after logout?
Knowledge

Markdown for humans. System prompt for agents.

Atlas treats your project's knowledge base as a first-class surface. Notes live as plain markdown in .atlas/knowledge/ next to your code — one source of truth, read by you and by every agent thread in the project.

  • Files, not a database. Subdirectories, frontmatter, real markdown. Versioned with your repo.
  • Save threads as knowledge. Pick any agent thread, export it as a note. The agent learns from your last conversation, not your repo's hot air.
  • Plays nicely with CLAUDE.md & AGENTS.md — no migration. Atlas reads what's already there.
Reference system

@ anything in your project.

Pull files, folders, branches, knowledge notes, commits, and entire threads into your prompts. Atlas resolves the references locally and hands the agent exactly the context it asked for — nothing more.

  • File and line refs. @src/auth.ts#L40-80 sends a slice, not the whole file.
  • Branches, commits, knowledge. @branch, @commit, @knowledge/auth-flow. Same syntax.
  • Cross-thread references. @thread:plan-acp-driver gives the agent a teammate's prior reasoning.

Editor

A real editor, not a textbox.

CodeMirror 6 with first-class support for JS, TS, Python, Rust, Go, Java, C++, JSON, YAML, Markdown, SQL, CSS, HTML, XML. Files are real files — ⌘S writes to disk.

Inbox

Never miss what your agents did.

Every meaningful agent event — permission prompts, completed streams, tool calls, knowledge saves, branch operations — surfaces in a unified inbox. Approve, dismiss, jump back to the thread.

  • Permission prompts up front. Agents don't run destructive commands without your eyes on them.
  • Per-session filtering. Many threads running? Filter to one. Mute noisy sources.
  • One-key jump. ⌘⇧I from anywhere. Click a row to land in the source thread.
Activity Log

Every meaningful event — chat sends, tool calls, file edits, git ops, terminal commands, knowledge writes — flows through a 500-event ring buffer in memory plus an append-only pinned log on disk. Searchable, filterable, JSON-expandable per row.

  • Source & project filters. Drill into one agent, one project, one kind of event.

Rust owns business logic

name: rust-owns-business-logic
type: feedback
description: all logic in Rust, React is view-only
feedback

Architectural rule: every piece of state and business logic lives in Rust. React is a view layer — it renders store snapshots and forwards intent over Tauri IPC, nothing more.

Why: a single source of truth survives window reloads and keeps performance predictable.

How to apply: new state goes in a Rust command + event, not a React hook. See [[permission-mode-sync]].
